**TokenSip** — самостоятельно размещаемый open-source шлюз между вашим приложением и провайдерами ИИ: **OpenAI, Anthropic, Gemini, DeepSeek и ещё 20+**. Он максимально использует кэширование промптов, убирает лишние токены и показывает каждый сэкономленный доллар.

## Зачем TokenSip?

Агенты и чат-приложения **пересылают весь диалог на каждом шаге**. Провайдеры тарифицируют повторяющийся контекст по **10–50% от обычной цены**, если правильно использовать кэширование промптов, — но большинство приложений этого не делает. TokenSip делает это автоматически:

- 🧠 **Работает с кэшем.** Автоматически добавляет `cache_control` для Anthropic и стабильный `prompt_cache_key` для OpenAI. Все оптимизации сохраняют префикс, поэтому кэш срабатывает на каждом шаге.
- 🪶 **Безопасно для агентов.** Профиль по умолчанию `balanced` никогда не удаляет то, что ещё нужно модели: последняя версия каждого файла и вывода команды остаётся целиком, ответы ассистента не меняются. `safe` передаёт неизменённые запросы **байт в байт**.
- 🎚️ **Компромисс выбираете вы.** Пять профилей от `off` до `extreme` (≈10% исходного промпта) с понятными предупреждениями о качестве.
- 🔌 **Без изменений кода.** Меняется только base URL. Работает со всеми SDK, а также с Claude Code, Codex, Gemini CLI, Aider, Cline.
- 🔐 **Безопасно и приватно.** Зашифрованное хранилище ключей, виртуальные ключи с бюджетами, промпты не сохраняются, 2FA, строгий CSP.

## 🧠 Новое в 2.0: контекстный движок, который считает экономику кэша

Все менеджеры контекста делают промпт *короче*. С кэшированием промптов это часто **убыточно**: кэшированные токены стоят 10% цены, поэтому удаление устаревшего вывода в начале длинной сессии агента заставляет провайдера заново обработать — и записать в кэш по 125% цены — всё, что идёт после него. В нашей симуляции без утечек кэша обрезка на каждом шаге оказалась **на 33–87% дороже** обычного кэширования. А обрезка «на глаз» удаляет код, который агенту ещё нужен.

TokenSip 2 задаёт два более точных вопроса:

1. **Устарела ли информация доказуемо?** Файл прочитан повторно, тесты перезапущены — новый результат показывает текущее состояние. Заменяется только старая копия — ссылкой на новый вызов. Последнее наблюдение всегда остаётся целиком, поэтому агенту не нужно ничего перечитывать или выводить заново.
2. **Дешевле ли удалить это *сейчас*, чем оставить?** Теневая модель кэша провайдера решает: применить, когда кэш холодный или перезапись окупается (`S·r·H ≥ (C−p)·(w−r)`), иначе дождаться бесплатного момента. Применённые изменения фиксируются, и префикс снова кэшируется со следующего шага.

**Cache Doctor** находит значения, которые незаметно ломают кэш, — время или id запроса в системном промпте, инструменты в другом порядке — и исправляет их, ничего не скрывая от модели.

| 720 одинаковых шагов агента, тарификация кэша Anthropic | Обычное кэширование | Обрезка на каждом шаге | **TokenSip 2** |
| --- | --- | --- | --- |
| Паузы дольше 5-минутного TTL кэша | $33.00 | $43.85 (+32.9%) | **$22.82 (−30.9%)** |
| Часы в системном промпте | $161.96 | $46.41 (−71.3%) | **$23.86 (−85.3%)** |
| Без пауз | $20.77 | $38.87 (+87.2%) | **$18.72 (−9.9%)** |

Запустите сами: `npx tokensip simulate`. С реальным провайдером доля промпта, прочитанная из кэша, для системного промпта с часами выросла **с ~6% до ~96%**. [Подробнее об устройстве (англ.)](docs/cache-economics.md)

## 🚀 Быстрый старт

```bash
npx tokensip
```

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:8787/v1", api_key="sk-...")
client.chat.completions.create(model="deepseek-chat", messages=[...])  # автоматически → DeepSeek
```

```bash
# Docker
docker run -d -p 127.0.0.1:8787:8787 -e TOKENSIP_SECRET="$(openssl rand -hex 32)" \
  -v tokensip-data:/data ghcr.io/imrx44/tokensip:latest

# Демо-панель с синтетическими данными (пароль: tokensip-demo)
npx tokensip demo
```

## 🎚️ Профили экономии

| Профиль | Отправляется промпта | Риск для качества | Что делает |
| --- | --- | --- | --- |
| `off` | 100% | нет | Чистый прокси: аналитика, бюджеты, кэш ответов |
| `safe` | 95–100% | **нет** | Точки кэширования, ключи маршрутизации кэша, стабильный порядок инструментов, пробелы |
| **`balanced`** (по умолчанию) | 55–95% | низкий | + исправления Cache Doctor, удаление устаревшего вывода с учётом экономики кэша, дедупликация результатов |
| `aggressive` ⚠️ | 40–70% | средний | + сжатие JSON, обрезка устаревшего вывода, окно диалога |
| `extreme` ⚠️ | **≈10%** | **высокий** | + бюджет контекста, меньше рассуждений, лимит ответа |

Измерено на примерах агентов из `examples/requests`: `balanced` — **≈−42%**, `extreme` — **−89…91%** токенов промпта.

## 🔐 Безопасность

- Ключи провайдеров и кэш ответов шифруются AES-256-GCM
- Виртуальные ключи (`tsk_…`) с месячным бюджетом, лимитами и сроком действия
- Промпты и ответы не сохраняются — только метаданные
- Одноразовый токен настройки, scrypt, 2FA, защита от CSRF, журнал аудита

Подробнее: [SECURITY.md](SECURITY.md) и [документация](docs).
